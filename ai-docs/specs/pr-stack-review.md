対象は #44 → #45 → #46 → #50 → #51 → #55。2026-11-12 (JST) に、実装時の会話を渡さない4人のレビュー担当で、状態・通知・教科別推定・画面操作を分担して確認した。修正差分は、さらに別の担当で再確認した。

## 再現した不具合と保存規則

| 不具合 | 再現条件 | 修正後 |
|---|---|---|
| Classroomから完了すると作業が続く | 作業中の課題を取り込みのTURNED_INで完了にする | 課題更新・作業記録の終了・作業状態の解除を同じD1 batchで保存する。40文の境界でも分割しない |
| 旧版の完了課題に未終了の作業が残る | 旧版で完了後も作業を開始し、完了統合のmigrationを適用する | 追加migration 0007で終了する。開始より前にはせず、本人の確認待ちにして推定へ混入させない。完了時刻・確定済み記録は変えない |
| 別の保存で見積もりが巻き戻る | 題名だけのPATCHの読み取り後に見積もり変更が先行する | 省略した項目は書き込まない。通常課題同士の独立した題名・見積もりの更新を両方保存する |
| 二重の完了通知、メモの0分制約の破壊 | 完了要求同士、またはメモ変換と古い見積もり変更が重なる | 読み取った種類と、変更対象の状態・締切を条件付きUPDATEで照合する。状態変更はupdatedAtも照合し、完了→再開の往復も検出する。競合は409 task_changedで通知・再計画を行わない |
| 取り込みとの競合で非通知完了から通知が出る | TURNED_INの取り込みが読み取った後、保存前に手動で通常完了・非通知完了する | 取り込みも実際に完了へ遷移できたIDだけを通知対象にする。先行した手動完了の時刻と非通知の選択を上書きしない。締切変更は完了遷移と分けて保存する |
| 競合した要求の締切履歴や作業終了が残る | 古い完了・締切変更の保存前に別の要求で更新・再開する | 履歴は直前のUPDATEが成功した場合だけINSERT SELECTする。作業終了はDB上で現在も閉じた課題・メモだけに限定する |
| 開始とメモ変換の競合で作業中のメモができる | 開始要求の読み取り後に完了・メモへ変更する。またはメモ変換の読み取り後に作業を開始する | 開始batchの各操作で現在も通常課題かつ未着手・作業中であることを確認する。メモ変換も必ず状態・updatedAtを照合する。開始できない場合に、別課題の作業も終了させない |
| メモ変換で他課題の通知が消える | 同じ上限まとめにメモへ変える課題と別の課題が含まれる | 未送信の集約だけ作り直す。他課題の元通知はdeferredへ戻す。送信済み・skippedの集約からは復元しない |
| メモ変換で既送信通知が再送される | 過去の送信済み保留まとめに含まれた課題をメモにする | 復元対象の集約先をpending/deferredに限定する |
| 保留解除後の上限まとめを追跡できない | 上限まとめが保留され、解除時にscheduledAtが変わる | 不変のcappedAtをpayloadへ保存する。旧形式は保留解除時に元のscheduledAtから補完する |
| 履歴の多い課題でメモ変換が失敗する | 125件以上の集約履歴がありD1の100バインド制限を超える | ID配列のバインドをやめ、SQLのサブクエリで集約先を参照する |
| メモの取り込み通知が送られる | Classroomの締切前倒し・再出現をメモに反映する | 生成時にdue_change/inbox通知を除外する。既存の待機通知もdispatchで種類を問わずメモを除外する |
| 科目候補表示中の最初の保存タップが失われる | 候補表示中に、候補より下の保存ボタンを押す | pointerdown/blurでは候補を閉じず、対象のclick完了後に閉じる。押下と解放の間にボタンの位置を動かさない |

updatedAtは課題の更新時にSQLのmax(updated_at + 1, now)で進める。同じミリ秒で完了→未着手→作業中へ往復しても、古い状態変更要求を成功させない。メモへの変換時は0分・非通知等の制約をまとめて保存し、既存メモの部分更新では指定された項目だけを正規化する。

## 検証方法

- workerの回帰検証はnode:sqliteで本物のSQL・migration・transactionを動かす。D1の100バインド制限も検査する。batch直前に待機点を入れて要求の順序を確定し、確率依存の同時実行テストにしない。
- 外部通信を差し替え、保存件数だけでなく通知回数、作業状態、締切履歴、副作用の有無も確認する。取り込みと完了の競合は実ルート・実notifySubmittedまで通し、HTTPだけを差し替える。本番DBへの書き込み・実通知の送信は行わない。
- 通知はpending/deferred/sent/skipped、保留まとめ、上限まとめ、他課題、taskId=nullの元通知、履歴125件を検証する。生成とdispatchも実際の経路を通す。
- モバイル幅・タッチ対応Chromiumで科目候補の選択、最初の保存、IME相当イベント、キーボード、クリア、未知の科目、遅延取得、候補スクロール後の選択など14項目を確認する。Android実機・実IMEでの確認とは区別する。
- 各PRのHEADを個別のディレクトリに展開し、worker/core/gas/webの型チェック、webのビルド、Biomeを確認した。6本とも成功した。修正後のスタック全体でも417テスト、型チェック、Web/GASビルド、Biome、frozen-lockfileでの依存インストールが成功した。
- 教科別推定は、同一教科の実績だけを変えた数値例と、他教科の実績を1000件追加した場合の不変性を検証した。今回、修正を要する不具合は確認しなかった。
