# 完了通知の非通知設定 (#48)

## 保存する設定

課題の `completionNotify` は真偽値で、作成時の既定値は `true`。既存データは migration `0005_completion_notify.sql` で従来どおり通知ありにする。課題追加・編集で通知を無効にできる。

更新で `completionNotify` を省略した場合は保存済み値を維持する。`false` に変更しても、締切前の催促や計画の扱いは変えない。この設定が止めるのは Discord / Slack の課題単位の完了報告であり、1日の作業時間の集計から実作業記録を消すものではない。

繰り返しを作成するときは元課題の設定をひな形へコピーし、将来の各回にも継承する。既存のシリーズやほかの回の設定は、ある回の編集だけで変更しない。Classroom 取り込み経由の完了でも中央の完了通知処理が保存済み設定を確認する。

## 一度だけ通知せず完了する

`PATCH /api/tasks/:id` に `{ status: "done", silent: true }` を送ると、この完了だけ通知しない。旧クライアントの `status: "submitted"` も完了へ正規化する。`silent: true` を完了以外の状態または状態指定なしで送った場合は入力エラーとする。

`silent` は操作専用であり、課題や繰り返しには保存しない。非通知で完了しても、完了時刻・作業記録の終了・再計画は通常の完了と同じ。再び未着手へ戻してから通常の完了にした場合は、保存済み `completionNotify` が有効なら通知する。完了のまま編集しただけでは通知しない。

中央の通知処理は送信前に課題がまだ完了状態であること、保存済みの通知設定、一回だけの非通知を確認する。取り込みからの完了にも同じ規則を適用し、通知前に再オープンした課題には送らない。

## 画面

課題の追加・編集に完了通知設定を配置する。一度だけの非通知完了は通常の完了と同じ強さで並べず、完了ボタン横の矢印から選択シートを開いた先に置く。行内の「操作」展開は廃止し、詳細は [完了操作の見直し](completion-actions.md) を正とする。説明だけの補助ラベルやヘルパーテキストは追加しない。

本番データの変更や migration の本番適用は行わず、ローカルで設定の既定値・保持・繰り返しへの継承・通常完了と一回の非通知を検証する。
