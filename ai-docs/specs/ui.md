# UI の方針(#29)

本人の希望: 情報密度はそれなりに高く、余白は少なく、色は少なく、グラデーションなし、影は極小。AI っぽい最大公約数的なデザイン(角丸の大きいカード、淡い色の面、大きなボタン、絵文字)にしない。とにかくシンプルに。

## トークン(`web/src/theme.css`)

Tailwind の既定のパレット・影・角丸は `@theme` で消してある(biome 2.2 が `--color-*: initial` を読めないので、このファイルだけ biome の対象外)。`bg-blue-600` や `rounded-xl`、`shadow-md` は**書いても効かない**。使えるのは次だけ。

| 用途 | クラス |
|---|---|
| 文字 | `text-ink`(本文・既定)/ `text-sub`(補助)/ `text-faint`(さらに弱い・空の表示) |
| 罫線 | `border-line` / `divide-line` |
| 面 | `bg-paper`(白)/ `bg-wash`(押したとき・無効の面。広い面には使わない) |
| 危険・期限切れ・致命 | `text-danger` / `border-danger` |
| 注意・未提出 | `text-warn` / `border-warn` |
| 塗り | 主要な操作のボタンと、選ばれたチップだけ `bg-ink text-paper` |
| 角丸 | `rounded-sm`(3px)と、点の `rounded-full` だけ |
| 影 | `shadow-edge`(下から出るシートの上端の線)だけ |

## 寸法

- 文字は 14px(`text-sm`)が基準。補助は 12px(`text-xs`)、見出しは `text-base`、ホームの締切だけ `text-lg`
- 余白: ページの左右 12px(`px-3`)、まとまりの間 12px(`gap-3`)、まとまりの中 4〜8px
- ボタンの高さは約 34px(`py-1.5`)。リストの行は `py-2`
- 数字は全体で `tabular-nums`、和文は `palt`

## 部品(`web/src/components/ui.tsx`)

- ボタン: `btnPrimary`(墨の塗り。1画面に1〜2個まで)/ `btnSecondary`(枠だけ)/ `btnDanger`(枠+赤い文字。塗らない)/ `btnGhost`(文字だけ)
- `chipClass(selected)`: 絞り込みや 30/60/90分 などの選択肢。丸いピルにしない
- `inputClass`、`Field`(上に小さいラベル)
- `PageHeader`(`text-base` の見出し+右に操作)、`SectionTitle`(小さい見出し+下の罫線)
- `listClass`: 罫線で区切ったリスト。カードを縦に並べる代わりに使う
- `Notice`(左の線+小さい文字。`tone` は plain / warn / danger)、`ErrorNotice`、`Tag`(小さな枠付きの札)、`Empty`
- 面を塗った箱(`bg-*-50` の囲み)は作らない。強調は左の 2px の線(`border-l-2 pl-2`)と文字の太さ・色で

## リスクの見せ方

`features/schedule/format.ts` の `RISK_STYLE`。余裕は色なし、注意は黄土、危険・致命は赤。面は塗らず、左の線と文字色だけ。

## しないこと

- 絵文字をアイコン代わりに使う(ステータスは小さな点)
- 1つの画面に色を3つ以上出す(墨・灰+赤か黄土まで)
- カードの入れ子、`rounded-full` のピル型ボタン、影

## 文言(#32 の続き)

本人の評: 「UI はいいが、文章が全体的に AI 臭い」。**書かないで済むなら書かない。** 本人が作って本人だけが使うアプリなので、使い方の説明はいらない。残すのは「判断を変える事実(数字・日時)」と「操作の名前」だけ。

### 規則

1. **画面の説明文を置かない**。「〜を並べます」「〜できます」「〜に届きます」のような前置き・案内、理論の注意書きは消す(必要なら ai-docs に残す)
2. **常体・体言止め**。です・ます、「〜しましょう」「〜しよう」「〜してください」、呼びかけ・励まし・あいさつ(「おかえり」「整えよう」「10分だけ触ろう」「始めてしまえば続けやすい」)は使わない
3. **事実と数字で言う**。ぼかし語(「少し」「ほとんど」「〜かもしれない」「見込み」「傾向」「約」)を使わず値を出す。出せる値がなければ、その行ごと出さない
4. **ラベルは名詞1〜2語**。「(任意)」「(日本時間)」は付けない(時刻はすべて JST。空欄でよい欄は空欄で分かる)。単位が要るときだけ「見積もり(分)」
5. **ボタンは短く**: 「保存」「削除」「追加」「やめる」「提出済み」。「〜する」「〜にする」は付けない。確認の肯定も「削除」
6. **空の状態は1語か短い句**: 「なし」「確認待ちなし」。次に何をすればいいかは書かない
7. **進行中は「…」付きの1語**: 「保存中…」「読み取り中…」。「(数秒かかります)」などの補足は付けない
8. **成功は出さないか1語**(「保存済み」)。画面が変わって分かるなら出さない
9. **エラーは「何が・どうだ」**: 「締切が未入力」「終了が開始より前」「通信エラー」「200字まで」。「〜してください」で終えない。サーバーのコードの文言は `core/domain/errors.ts`
10. **長さは `1h30m` `45m` `3h`**(`formatDuration`)、空きや余裕の量は `6.6h` `40m`(`formatHours`)。日時は `10/14(水) 23:59`、相対は `3日後` `今週`
11. **計算の根拠(plan §2.2-1)は文ではなく数字で**: 「空き 6.6h / 必要 4.4h(普段のペース)」
12. **絵文字は使わない**(webhook の投稿の ✅ は plan §3.11 の形なので例外)

### 例

| 前 | 後 |
|---|---|
| 余裕のあるタスクを、次の空き時間にやると生み出せる余裕が大きい順に並べます。 | (消す) |
| やることはありません。課題が出たら「＋ 追加」から登録する | 未完了なし |
| この時刻までに始めないと、普段のペースでは収まらなくなる(残り空き 6.6h / 必要 4.4h) | 空き 6.6h / 必要 4.4h(普段のペース) |
| 普段のペースでは足りない。本気が必要 | 普段のペースでは間に合わない |
| まとまった時間が要るので、大きく空いている今やる価値が高い | まとまった時間が要る |
| 写真から課題を読み取っています…(数秒かかります) | 読み取り中… |
| 完了(未提出)です。提出したら「提出済み」にしてください | 未提出 |
| タイトルを入力してください | タイトルが未入力 |
| 通知(10分だけ触ろう: X / 始めてしまえば続けやすい。必要な時間は2h、締切 …) | 着手: X / 必要 2h・締切 10/14(水) 23:59 |
| 通知(おかえり、今日の見通し) | 今日 |

### 通知・ダイジェスト(サーバーが作る文)

- タイトルは「<種類の語>: <課題名>」。種類の語は固定(「着手」「締切 24h前」「至急」「提出は?」など)
- 本文は事実を「・」か改行で並べるだけ(締切、必要な時間、着手の限界、最初の一歩)。命令・励まし・損失の煽りは書かない(plan §2.3)
- plan §3.8 の「同じ文面を繰り返さない」は、事実の並べ方を変える程度の言い回しのローテーションで満たす
