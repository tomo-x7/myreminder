# 課題の入力と操作 (#41・#43)

## 最初の一歩

「最初の一歩」の入力と「まず」の表示は廃止する。追加・確認・編集フォームの状態からも削除し、保存 API へは互換フィールド `firstStep: null` を渡す。古い課題や古い API 応答に値が残っていても画面へ出さず、新規の課題へ引き継がない。

着手時刻の選択は独立した機能として残す。ホームの課題操作は「始める」「完了」「いつに回す?」に揃え、「提出済み」は表示しない。

## 実績の表示

見積もり欄のヘルパーテキストは使わない。「実績」を展開すると、課題名・見積もり・実績の表を表示する。取得するデータの範囲は科目優先の参照 API と一致する。実績がないときは表ごと出さない。AI による見積もりであることだけを示す補助ラベルも出さない。

## 写真の選択と撮影

入力方法の「写真」を押すと「写真を選ぶ」「撮影」の操作を開く。写真の操作を開く前の文章や手入力カードは保持する。

- 「写真を選ぶ」は `accept="image/*"` のファイル入力を開き、`capture` は指定しない。端末の写真ライブラリやファイル選択から撮影済みの画像を追加できる。
- 「撮影」は独立した `capture="environment"` のファイル入力を開く。実際のカメラ選択 UI はブラウザと OS に従う。
- どちらも選択が成立した時点で同じ画像変換・解析・確認カードへ進む。
- 選択を取り消したときは解析せず、入力済みの内容を保持する。
- ファイル入力は読み取り後に空に戻し、同じ写真の再選択も受け付ける。
- 解析中は写真操作を無効にし、重複解析を防ぐ。共有メニュー経由の画像取り込みは既存の経路を維持する。

写真操作の開閉状態は `aria-expanded` と `aria-controls` で伝え、操作はキーボードからも使える通常のボタンとする。狭い画面は操作を折り返す。

画像の縮小・向き補正・JPEG 変換・プレビューの解放と、解析失敗時の手入力への切り替えは既存の処理を使う。写真解析の実機動作は本人が確認済み。UI のスクリーンショットは PR に添付し、リポジトリへ含めない。
