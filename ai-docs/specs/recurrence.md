# 繰り返し(#34)

本人の依頼: 手動・AI の解析を問わず、登録時に毎週・毎月などの繰り返しを付けたい。回数や終わりの日も指定できるとよい。作り方(まとめて作るか、繰り返すか)は任せる。

## 方式: シリーズ+先の分だけ作る

繰り返しは **シリーズ**(`task_series`)として持ち、回(普通のタスク)は先の分だけ作る。

- 作成時に全部の回を作る方式は採らない。毎週×15回で一覧が埋まり、ノイズになる(本人はノイズを嫌う)。無期限も扱えない
- 計画は14日先までしか見ない(plan §3.5)ので、それより先の回を作っても計画には効かない

**作る範囲**: 締切が `now + 14日` 以内の回すべて。加えて、締切が `now` より後の回が1つもなければ次の1回(毎月でも次の回が常に見える)。締切が `now` 以前になる回は作らずに飛ばす(過去のタスクを起点に繰り返しを付けたとき、過ぎた回を作らない)。

**作るタイミング**: シリーズを作ったとき、毎時0分の cron(通知の再計画の前)。

**各回は普通のタスク**: 個別に編集・削除・提出・取り下げしてよい。どこまで作ったかはシリーズの `materialized_count`(次に作る回の番号)で持つので、消した回は作り直さない。

## ルール

| 項目 | 値 |
|---|---|
| `freq` | `weekly` / `monthly` |
| `interval` | 1〜12(毎週の 2 = 隔週) |
| 基準 | 最初の回の締切 `anchorDueAt` |
| 毎週 | `anchorDueAt + k × interval × 7日`(JST は夏時間がないので ms の足し算でよい) |
| 毎月 | JST の年月を `k × interval` か月進める。日は基準の日(その月になければ月末)、時刻は基準と同じ。前の回からではなく、常に基準から計算する(31日 → 2/28 → 3/31) |
| 終わり | `count`(最初の回を含む回数、1〜100)/ `until`(JST の日付。その日の 23:59 までの締切を含む)/ どちらもなし(無期限)。両方は不可 |

`k` は回の番号(最初の回が 0)。

**各回にコピーするもの**: `title` `courseId` `category` `estimateMin` `estimateSource` `minBlockMin` `firstStep` `note`。`releaseAt` と `plannedStartAt` は「締切からの差(分)」で持ち、各回の締切に足す(「月曜締切を前日の日曜 21:00 に始める」が毎回続く)。状態は `todo` から。

## データ

- `task_series`: `id`, `title`, `course_id`(set null), `category`, `estimate_min`, `estimate_source`, `min_block_min`, `first_step`, `note`, `freq`, `interval`, `anchor_due_at`, `release_offset_min`, `planned_start_offset_min`, `count`, `until`, `materialized_count`, `stopped_at`, `created_at`, `updated_at`
- `tasks` に `series_id`(→ `task_series`、set null)と `series_index`。`(series_id, series_index)` は一意(作るのを冪等にする)

## API(足すだけ。`apiVersion` は変えない)

- `POST /api/tasks` に省略可能な `repeat: { freq, interval?, count?, until? }`。付けると、最初のタスクを作ってからシリーズを作り、そのタスクを回 0 として紐付け、先の回を作る。応答は最初のタスク(今までどおり)
- `POST /api/tasks/:id/repeat` `{ freq, interval?, count?, until? }`: 既存のタスク(シリーズなし)を回 0 にしてシリーズを作る。すでにシリーズに属していれば 409 `already_repeating`
- `GET /api/series`: シリーズの一覧(止めたものも含む)。一覧・編集画面で「毎週」「隔週」「毎月」と回数を出すのに使う
- `POST /api/series/:id/stop`: 止める(`stopped_at`)。締切が `now` より後で、未着手(`todo`)かつ作業記録のない回は消す。応答 `{ deleted: n }`
- タスクの応答に `seriesId` と `seriesIndex` が増える

## AI の解析

- 出力に省略可能な `repeat: { freq, interval } | null` を足す。文に「毎週」「隔週」「毎月」など繰り返しがはっきり書いてあるときだけ入れる。終わりは入れない(確認カードで決める)
- 確認カードの既定値として入れる。本人が外せる

## 画面

- **確認カード**(手入力・AI 共通)に「繰り返し」: チップ「なし / 毎週 / 隔週 / 毎月」。選んだら終わり「無期限 / 回数 [n] / 終了日 [日付]」。下に次の3回の締切と合計を出す: `10/19(月)・10/26(月)・11/2(月)… 計15回`
- **受信箱の追加**(取り込み)では出さない。取り込み元が毎回別の課題として出すので重複する
- **タスクの編集画面**: シリーズに属していれば `毎週 ・ 3回目 / 全15回`(無期限なら `毎週 ・ 3回目`、終了日なら `毎週 ・ 3回目 ・ 12/25まで`)と「以降を止める」。属していなければ「繰り返す」で確認カードと同じ選択肢を出す
- **一覧の行**: 小さな `Tag`「毎週」「隔週」「毎月」

日付の計算は、サーバー(`worker/src/planner/recurrence.ts`、テストあり)と、確認カードの予告用に `core/src/domain/recurrence.ts` の両方に置く(core は worker の実行コードを import できないため。同じ計算であることをコメントで示す)。

## 今はやらないこと

- シリーズのひな形の編集(「以降の回にも反映」)。各回は個別に直す。見積もりは実績から学習されるので、ひな形を直す必要は小さい
- 「第2月曜」のような曜日指定の毎月、毎日、平日だけ
