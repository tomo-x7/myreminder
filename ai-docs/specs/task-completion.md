# 課題の完了と操作

Issue #40 / #41。2026-11-10 の本人の依頼を正とし、従来の作業完了と提出済みの区別を廃止する。

## 状態と移行

状態は未着手 `todo`、作業中 `doing`、完了 `done`、取り下げ `dismissed` とする。完了は提出も含めて終わったことを意味し、未提出という中間状態は作らない。

migration `0004_unify_task_completion.sql` は既存 `submitted` を `done` に変更し、既存 `done` を含め、完了時刻がなければ最終更新時刻で補う。過去の完了通知は再送しない。古い未提出確認の送信待ちも停止する。本番DBへはこの作業中にmigrationを実行しない。

`submitted` の enum、`submittedAt` の列/API名、webhook の `submitted` イベント名は旧クライアント・保存済み設定との互換性のため残す。古い更新リクエストの `submitted` は `done` に正規化する。画面の選択肢とフィルターには「完了」だけを表示し、旧 `?s=submitted` も完了へ案内する。

## 完了通知と作業記録

未完了から完了に変更したとき、確定済みの作業時間と見積もりを含む既存の Discord / Slack 通知を「完了」の文面で送る。完了のまま保存しても通知しない。未着手・作業中・取り下げへ戻す場合は完了時刻を消し、再び完了にしたときは新たな完了として通知する。

完了時はその課題の開いている作業記録を閉じ、本人の作業中状態も解除する。進捗を100に書き換えないため、未着手に戻した課題も残り時間を再計算できる。完了・取り下げの課題は直接開始できず、編集で未着手へ戻してから開始する。画面は処理中の操作を無効にして二重送信を防ぐ。

完了課題は計画・未完了件数・締切通知・未提出確認・ダイジェストから外す。送信待ち通知についても送信時に完了を検出して破棄する。ふりかえりは互換名 `submittedAt` を完了時刻として使い、画面では完了した課題として表示する。

Classroom の `TURNED_IN` は完了に対応し、すでに完了した課題には重ねて通知しない。`RECLAIMED_BY_STUDENT` は従来どおり未着手へ戻し、完了時刻を消して提出取消を通知する。取り込み元そのものの「提出済み」という状態名は外部状態なので維持する。

## 一覧からの開始・完了

最優先以外の課題も一覧の各行から「開始」「完了」を操作できる。課題名のリンクと操作ボタンを別の領域にし、編集画面に入る必要をなくす。作業中の課題には開始を無効にして作業中と表示する。別課題の開始は既存の作業開始APIを使い、前の作業記録を閉じて切り替える。処理中は一覧の操作を無効にし、失敗は画面に表示する。ボタンのアクセシブル名には課題名を含める。
