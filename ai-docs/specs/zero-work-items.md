# 作業時間を持たないメモ (#49)

2026-11-10 の本人確認に基づく。表示名は「メモ」、内部値は `taskKind: "note"`。通常の課題は `taskKind: "work"` とする。負の見積もりなどの特別な数値で種類を表さない。

## 保存と移行

migration `0006_zero_work_items.sql` で tasks と task_series に `task_kind` を追加する。既存項目はすべて work になり、過去の見積もり・通知設定を変更しない。

メモはサーバーで見積もり0分、完了通知なし、着手時刻なし、公開日時なしへ正規化する。クライアントが別の値を送ってもこの制約を維持する。通常の課題は引き続き1分以上の整数を必要とし、負数はメモでも受け付けない。メモから通常の課題へ変更する API では、正の見積もりを明示する必要がある。

締切・教科・種類・備考・繰り返しは従来の項目を使う。締切は既存の課題と同様に必須。繰り返しのひな形と作成される各回にも taskKind と完了通知設定をコピーする。既存シリーズのある1回を変更しても、ほかの回やひな形は書き換えない。

## 計画・通知・実績

メモは通常の一覧と完了一覧で管理するが、開始操作は出さず、作業開始 API と手動作業記録の新規作成も拒否する。計画の割り当て・余裕・山場・期限切れの催促・通知の本文に含めない。過去の実績があっても見積もり学習とキャパの学習には使わない。取り下げた通常課題の実績は従来どおりキャパに使う。

完了時刻と完了状態は通常どおり保存し、Discord / Slack の課題単位の完了通知は設定にかかわらず送らない。既存の1日の作業実績の報告は別の機能であり、過去の記録そのものを消すものではない。

作業中の通常課題をメモに変更した場合は作業記録を閉じ、作業中状態を解除する。作業中のまま保存する API 入力は拒否する。既存の作業履歴は削除しない。

変更前に生成された個別の催促は停止する。既に本文が整形された未送信の自動まとめは破棄し、最新の課題集合で再計画する。保留のまとめから外したほかの課題は deferred に戻し、次の送信処理で再構成する。送信時にも taskKind を確認し、メモへ個別の催促を送らない。

## 1行入力

先頭に `メモ` と半角または全角スペースを置いた場合だけ明示指定として扱う。例: `メモ 提出先を確認`。タブ、明示的な `メモ:` / `メモ：` も受け付ける。

`メモリの課題`、`メモ帳`、`メモする`、文章途中の「メモ」は通常の課題として扱う。空の `メモ` / `メモ ` は内容未入力として候補を作らない。先頭の余白は無視する。

明示指定は AI に渡さず、指定後の文章をタイトルとする確認カードを返す。日付の自動抽出は行わず、締切は確認画面で入力する。写真・告知文からの自動メモ判定は行わない。どの経路も確認カードの保存操作を必要とし、解析だけで登録しない。

## 画面

追加・編集の「種類」で、通常の課題の分類とメモを一つの欄から選ぶ。詳細は [種類と科目の選択](task-type-course-picker.md) を正とする。メモでは見積もり・実績参照・着手時刻・公開日時・完了通知設定を表示しない。一覧の主操作は完了だけとする。通常の課題とメモをフォーム内で往復した際は入力済みの値を保持し、保存時に正規化する。保存済みのメモを通常課題へ変更する場合は、見積もり60分・最小単位30分・完了通知ありを初期値にする。

補助文やセカンダリラベルは追加しない。備考欄の名前は「備考」とし、項目名の「メモ」と区別する。

## 検証

正規化・通常0分拒否・繰り返し・通知設定の省略・完了通知拒否・催促生成除外・明示キーワード境界を自動テストする。ローカル API で作業中からの変換、旧通知の無効化と別課題の保留維持、開始・実績登録の拒否を確認する。本番 DB の更新・migration・デプロイはこの変更では実施しない。
