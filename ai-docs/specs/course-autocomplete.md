# 科目の直接入力と補完 (#56)

2026-11-11 の本人の追加要望を正とする。科目を選択シートへ移していた直前の設計を改め、科目欄へ直接入力して、途中までの名前から補完できるようにする。追加・AI確認・編集は共通の `CoursePicker` を使う。

## 入力と候補

科目欄は編集可能な combobox とする。フォーカス時と入力時に、入力欄の直下へアプリ内の候補一覧を表示する。ネイティブ `datalist` や別の選択シートは使わない。表示は通常のフォームの流れに含め、親シートのスクロール領域から切れてしまう絶対配置のポップアップにしない。

入力した文字列を、科目名と別名から NFKC・大文字小文字・空白を正規化して絞り込む。候補の選択で正式な科目名へ補完する。完全一致または別名の完全一致でも科目IDを解決する。候補が複数あるだけでは、別の科目を勝手に確定しない。

空欄では「なし」とすべての登録候補を表示する。文字があるときは44px以上のクリア操作を使え、空欄にして科目なしへ戻せる。候補は44px以上の行とし、長い一覧は入力欄直下でスクロールする。未登録科目を作成する機能は追加しない。

## フォーカスとキーボード

検索文字の更新で入力欄を作り直さない。候補をタップしたり候補一覧をスクロールしたりする際に、blurで選択前の候補を消さない。候補選択後は入力欄にフォーカスを残す。外側の操作・Tabで候補を閉じ、Escは親の追加シートを閉じずに候補だけ閉じる。

外側のボタンを押すポインタ操作では、押下やblurの時点で候補を閉じない。クリックが成立してから閉じ、候補の高さが消えて保存などのボタンが押下位置から移動することを防ぐ。保存は最初のタップで実行する。

上下矢印で候補を移動し、Enterで選ぶ。日本語IMEの変換中、`isComposing` またはキーコード229のEnterは候補の確定に使わない。`aria-expanded`、`aria-controls`、`aria-activedescendant` と listbox/option で候補の状態を伝える。

表示領域がキーボード等で変わったときは候補一覧の高さを制限し、必要なら親のスクロール位置を調整して入力欄と候補を画面内に収める。文字を入力するたびにページをスクロールし直さない。

## 下書きと保存

追加・確認画面は入力中の科目名を下書きに保持する。途中までの入力は候補選びの最中として扱い、「未登録の科目」のエラーを表示しない。候補を閉じて入力欄から離れた後、未登録名なら従来のエラーを表示する。登録されていない名前を保存した場合は、従来どおり科目なしになる。

編集画面は登録済みの科目IDで保存する。不一致の未確定文字列は入力欄の標準検証で保存を止め、以前の科目IDを無言で保存しない。blurしただけでは入力を以前の名前へ戻さない。登録候補の選択、完全一致、または空欄への変更で再び保存できる。

科目一覧や外部の選択値が遅れて届いても、入力中の文字を上書きしない。説明文・タグライン・セカンダリラベルは追加しない。スクリーンショットはリポジトリに含めない。
