# 完了操作の見直し (#52)

2026-11-11 の本人の指摘に基づき、一覧の行内に「操作」を展開する方式を廃止する。小さなテキストを狙わせず、選択肢を開くためにほかの行が動くことも避ける。

## 主操作と別の完了方法

通常の「完了」は直接実行する主操作として維持する。その隣に下向き矢印の独立したボタンを接続した形で置く。どちらも高さ44px以上、矢印は幅も44px以上とし、親指で押せる領域を確保する。

矢印は押しただけでは完了しない。下から選択シートを開き、幅いっぱい・高さ48px以上の「通知せず完了」を押したときだけ、一度の非通知完了を実行する。独立した「操作」テキストや補助説明は置かない。シートの見出しには操作対象の課題名を使う。

一覧ではメモと保存済みの完了通知設定が無効な課題に矢印を出さない。どちらも通常の「完了」自体が通知を送らないため、同じ結果の選択肢を重ねない。ホームと夜の確認は計画APIの既存の型を使い、非通知操作を選べるようにする。

## 共通の動作

一覧、ホームの次の課題、夜の確認で `CompleteAction` を共有する。通常の操作は `silent: false`、選択シートの操作は `silent: true` として既存の更新処理を呼ぶ。完了時刻・作業記録の終了・エラーの扱いは従来と同じ。

処理中は完了と矢印を無効にする。一覧では既存の共通処理中状態を使い、ホームと夜の確認では開始・後回しも同時操作できないようにする。狭い画面では操作列を折り返し、ボタンを縮めて押しにくくしない。

選択シートは共通 `ActionSheet` を使い、画面内へ表示する。キーボードのフォーカスはシート内に閉じ込め、キャンセル・背景タップ・Esc で閉じる。キャンセルでは完了を呼ばず、呼び出し元が残っていればフォーカスを戻す。開閉で一覧の行の高さは変えない。

## 検証

Web の型チェック・ビルド・Lint を実行する。モバイル幅で操作領域、シートの位置、一覧の行の高さの不変、キャンセル時の非実行、フォーカス復帰、通常/非通知のAPI入力、メモと通知無効課題で矢印がないことをブラウザで確認する。スクリーンショットはリポジトリ外へ保存する。
